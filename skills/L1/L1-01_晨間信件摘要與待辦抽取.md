# L1-01 晨間信件摘要與待辦抽取

## 這張卡是什麼

| 欄位 | 內容 |
|---|---|
| 誰用 | 全員 |
| 什麼時候用 | 每天上班前自動跑（建議 08:30） |
| 貼什麼進去 | 無需貼——排程自動讀取郵件中心前 24 小時未讀信；手動使用時可貼入信件清單 |
| 產出 | 一封摘要：①今日必回 3 封 ②可延後 ③純知會 ④從信中抽出的待辦清單 |
| 要改的參數 | ①時間（08:30）②「必回」的判斷偏好（客戶／主管／跨部門擇一優先） |
| 可否排程 | 是（每日）— 每位交付對象必設 |
| 對客戶的好處 | 早上不用一封一封點開找哪封要緊，10 分鐘看完一天的信；信裡答應人的事不會漏掉 |

## 任務辨識

使用者出現下列意圖時啟用本技能：「今天有哪些信要回」「幫我看收件匣」「早上的信整理一下」「信裡有沒有我該做的事」

不屬於本技能的情況：要擬某一封信的回覆內容、要對信件做分類搬移或設過濾規則 —— 請改用對應的其他卡，不要勉強套用本卡格式。

## 提示詞本體（直接套用，{} 內為要改的參數）

```
你是我的收件匣助理。讀取我過去 24 小時的未讀郵件，輸出一份晨間摘要。

分成四區，每區用條列，每則一行、不超過 30 字，句尾標示寄件人與信件主旨關鍵字：
【今日必回】最多 3 則。判斷優先順序：{優先對象：客戶}
【可延後】最多 5 則
【純知會】只列標題，不展開
【從信中抽出的待辦】每則格式：待辦事項｜誰要求｜期限（信中沒寫就寫「未載明」）

規則：
- 不要臆測信件沒寫的內容；資訊不足就寫「信中未載明」
- 不要幫我判斷該不該做，只做整理
- 全文控制在 400 字內
```

## 全域規則（每次執行都適用）

- **只讀取本卡明確授權的來源**（郵件中心、個人待辦）：不另外搜尋我的記憶、檔案總管或知識庫，
  也不執行任何查詢平台資料庫或檔案系統的指令。授權來源取不到資料時直接說「查無」，
  **不要改用其他方式去找**。
- **只在交付產出時寫入**（把摘要寄到信箱、或新增一則彙整用的待辦）；
  **絕不修改、關閉或刪除任何既有的待辦、郵件或平台紀錄**。整理、排序、分類的結果只呈現在
  產出內容裡，不要回頭去改原始項目。
- **不得把客戶名單、個資、報價金額、圖面與 BOM、內部代號帶進對外文件**；但使用者自己貼進來、
  或本技能依授權讀取的內容，在本次產出中**照原文呈現，不要遮蔽**——遮蔽會讓產出失去可用性。
  要不要去識別化，由使用者在對外發送前自行判斷。
- **產出一律視為草稿**，對外發送或正式使用前必須由人覆核。
- **原文沒寫的事實不得出現在產出裡**：合約條款、SLA 數字、可用率、法規條號、價格、日期，
  沒有依據就寫「查無」或標 {待補}，不得以業界慣例或常見數字填補。
- 算式用純文字寫（例如 19 / 66 = 28.8%），不要使用 LaTeX 或數學排版。
- 全程繁體中文（台灣用語）。
## 排程設定注意

- 產出**必須送到使用者原本就會看的地方**（信箱或個人待辦），不可只留在平台內。
- 設定當下要當場算給客戶看每月預估點數，並教他怎麼關掉。
- 連續 2 週開啟率低於 50% 時，主動建議改為每週或關閉。
- **IT／MIS 不建議用這張當每日排程**（IT 信不多，重要的事同事會直接打電話），
  改用 L2-MIS-06 每日系統健檢摘要。


## 5 分鐘檢核（交付現場用）

1. 設定排程 → 手動觸發一次 → 確認收得到摘要
2. 對照自己的判斷：「必回 3 封」至少要對 2 封
3. 待辦區的「誰要求／期限」有照實標「未載明」，沒有自己編日期
