# L1-15 本週知識沉澱進 Wiki

## 這張卡是什麼

| 欄位 | 內容 |
|---|---|
| 誰用 | 全員 |
| 什麼時候用 | 每週五（建議 17:00） |
| 貼什麼進去 | 無需貼——排程讀取本週平台對話紀錄 |
| 產出 | 本週可重複使用的問答／做法，整理後存進企業 Wiki |
| 要改的參數 | ①存到 Wiki 哪個分類 |
| 可否排程 | 是（每週） |
| 對客戶的好處 | 問過一次的東西不用問第二次；人員異動時，做法留得下來 |

## 任務辨識

使用者出現下列意圖時啟用本技能：「把這週的做法存起來」「知識沉澱」「以後不用再問一次」

不屬於本技能的情況：會議紀錄的歸檔、客戶文件的整理 —— 請改用對應的其他卡，不要勉強套用本卡格式。

## 提示詞本體（直接套用，{} 內為要改的參數）

```
整理我本週在平台上的對話，挑出「以後還會再用到」的內容，存進 Wiki 分類 {分類名}。

篩選標準：同一類問題問了 2 次以上，或產出被我實際採用的
每則格式：
標題｜適用情境｜當時用的提示詞｜要注意的地方

規則：
- 涉及客戶名稱、金額、個資的內容一律略過不存
- 只整理，不重新生成內容
```

## 全域規則（每次執行都適用）

- **只讀取本卡明確授權的來源**（郵件中心、個人待辦）：不另外搜尋我的記憶、檔案總管或知識庫，
  也不執行任何查詢平台資料庫或檔案系統的指令。授權來源取不到資料時直接說「查無」，
  **不要改用其他方式去找**。
- **只在交付產出時寫入**（把摘要寄到信箱、或新增一則彙整用的待辦）；
  **絕不修改、關閉或刪除任何既有的待辦、郵件或平台紀錄**。整理、排序、分類的結果只呈現在
  產出內容裡，不要回頭去改原始項目。
- **不得把客戶名單、個資、報價金額、圖面與 BOM、內部代號帶進對外文件**；但使用者自己貼進來、
  或本技能依授權讀取的內容，在本次產出中**照原文呈現，不要遮蔽**——遮蔽會讓產出失去可用性。
  要不要去識別化，由使用者在對外發送前自行判斷。
- **產出一律視為草稿**，對外發送或正式使用前必須由人覆核。
- **原文沒寫的事實不得出現在產出裡**：合約條款、SLA 數字、可用率、法規條號、價格、日期，
  沒有依據就寫「查無」或標 {待補}，不得以業界慣例或常見數字填補。
- 算式用純文字寫（例如 19 / 66 = 28.8%），不要使用 LaTeX 或數學排版。
- 全程繁體中文（台灣用語）。
## 排程設定注意

- 寫入 Wiki 前應先讓使用者確認清單，避免把敏感內容存成公開條目。
- 設定當下揭露每月預估點數並教客戶怎麼關。


## 5 分鐘檢核（交付現場用）

1. 手動觸發一次，確認挑出來的確實是重複用過的
2. 沒有把含客戶名或金額的內容存進去
3. 每則都附得出「當時用的提示詞」
