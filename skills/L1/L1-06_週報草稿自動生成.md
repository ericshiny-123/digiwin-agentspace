# L1-06 週報草稿自動生成

## 這張卡是什麼

| 欄位 | 內容 |
|---|---|
| 誰用 | 全員 |
| 什麼時候用 | 每週五下午自動跑（建議 16:00） |
| 貼什麼進去 | 無需貼——排程讀取本週個人待辦完成紀錄與會議紀錄 |
| 產出 | 週報草稿：本週完成／進行中／下週計畫／需要協助 |
| 要改的參數 | ①時間（週五 16:00）②我的職務範圍一句話 |
| 可否排程 | 是（每週）— 建議必設 |
| 對客戶的好處 | 週五下午不用從頭想「這週做了什麼」，改一改就交得出去 |

## 任務辨識

使用者出現下列意圖時啟用本技能：「幫我生週報」「這週做了什麼」「週報草稿」

不屬於本技能的情況：資安事件週報、對外的專案結案報告 —— 請改用對應的其他卡，不要勉強套用本卡格式。

## 提示詞本體（直接套用，{} 內為要改的參數）

```
讀取我本週（週一至今）的個人待辦完成紀錄與會議紀錄，產出週報草稿。

我的職務範圍：{一句話描述}

輸出四區，每區條列，每條不超過 25 字：
【本週完成】只列已完成的，附完成日
【進行中】附目前卡在哪
【下週計畫】從未完成待辦推導
【需要協助】會議紀錄中標為「未指派」「待確認」的事項

規則：
- 只能用系統裡實際存在的紀錄，不足就寫「本區無紀錄」，不得憑空補寫工作內容
- 不要加形容詞（如「順利」「積極」），只寫事實
- 全文控制在 400 字內

最後一步（必做，不可省略）：用郵件工具的 send 動作，把這份週報草稿寄到我自己的信箱，
主旨「週報草稿 {本週起訖日}」。寄出後在回覆最後一行寫「已寄出」或寄送失敗的原因。
產出只留在平台對話裡不算完成。
```

## 全域規則（每次執行都適用）

- **只讀取本卡明確授權的來源**（郵件中心、個人待辦）：不另外搜尋我的記憶、檔案總管或知識庫，
  也不執行任何查詢平台資料庫或檔案系統的指令。授權來源取不到資料時直接說「查無」，
  **不要改用其他方式去找**。
- **只在交付產出時寫入**（把摘要寄到信箱、或新增一則彙整用的待辦）；
  **絕不修改、關閉或刪除任何既有的待辦、郵件或平台紀錄**。整理、排序、分類的結果只呈現在
  產出內容裡，不要回頭去改原始項目。
- **不得把客戶名單、個資、報價金額、圖面與 BOM、內部代號帶進對外文件**；但使用者自己貼進來、
  或本技能依授權讀取的內容，在本次產出中**照原文呈現，不要遮蔽**——遮蔽會讓產出失去可用性。
  要不要去識別化，由使用者在對外發送前自行判斷。
- **產出一律視為草稿**，對外發送或正式使用前必須由人覆核。
- **原文沒寫的事實不得出現在產出裡**：合約條款、SLA 數字、可用率、法規條號、價格、日期，
  沒有依據就寫「查無」或標 {待補}，不得以業界慣例或常見數字填補。
- 算式用純文字寫（例如 19 / 66 = 28.8%），不要使用 LaTeX 或數學排版。
- 全程繁體中文（台灣用語）。
## 排程設定注意

- 產出必須寄到使用者信箱或個人待辦。
- 設定當下要揭露每月預估點數並教客戶怎麼關。


## 5 分鐘檢核（交付現場用）

1. 手動觸發一次，確認四區都有內容或誠實寫「本區無紀錄」
2. 沒有出現系統裡查不到的工作項目
3. 沒有「順利推進」這類形容詞
