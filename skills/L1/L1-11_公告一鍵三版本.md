# L1-11 公告一鍵三版本

## 這張卡是什麼

| 欄位 | 內容 |
|---|---|
| 誰用 | 行政、人資、主管 |
| 什麼時候用 | 要發內部公告時 |
| 貼什麼進去 | 一段口述的公告重點 |
| 產出 | 三版本：正式公文／群組親切版／簡訊 60 字版 |
| 要改的參數 | ①生效日期 |
| 可否排程 | 否 |
| 對客戶的好處 | 一次寫好公文、群組、簡訊三種版本，不用改三遍，也不會三個版本說法不一致 |

## 任務辨識

使用者出現下列意圖時啟用本技能：「幫我寫公告」「這個要通知全公司」「群組版跟公文版都要」

不屬於本技能的情況：對外客戶函文、新聞稿 —— 請改用對應的其他卡，不要勉強套用本卡格式。

## 提示詞本體（直接套用，{} 內為要改的參數）

```
把以下重點寫成內部公告，輸出三個版本：
【A 正式版】公文體，含主旨、說明、生效日
【B 群組版】口語、親切，3～5 行
【C 簡訊版】60 字內，只留「什麼時候、要做什麼」

生效日期：{日期}
規則：三版本的事實內容必須一致；重點裡沒提到的細節不得補寫，缺的寫 {待補}。

---
（貼上重點）
```

## 全域規則（每次執行都適用）

- **只使用使用者在本次對話中提供的內容**：不主動搜尋郵件中心、我的記憶、檔案總管、知識庫或
  個人待辦，也不執行任何查詢平台資料庫或檔案系統的指令。遇到不認識的公司名、人名或專案名，
  一律當成使用者提供的既定資訊直接使用，**不要去查**；資料不足就標 {待補}。
- **本技能為唯讀輸出**：不新增或修改待辦、不寫入檔案、不變更平台紀錄、不寄送任何郵件。
- **不得把客戶名單、個資、報價金額、圖面與 BOM、內部代號帶進對外文件**；但使用者自己貼進來、
  或本技能依授權讀取的內容，在本次產出中**照原文呈現，不要遮蔽**——遮蔽會讓產出失去可用性。
  要不要去識別化，由使用者在對外發送前自行判斷。
- **產出一律視為草稿**，對外發送或正式使用前必須由人覆核。
- **原文沒寫的事實不得出現在產出裡**：合約條款、SLA 數字、可用率、法規條號、價格、日期，
  沒有依據就寫「查無」或標 {待補}，不得以業界慣例或常見數字填補。
- 算式用純文字寫（例如 19 / 66 = 28.8%），不要使用 LaTeX 或數學排版。
- 全程繁體中文（台灣用語）。
## 5 分鐘檢核（交付現場用）

1. 用一則真的要發的公告跑
2. 三個版本的日期、對象、動作完全一致
3. 沒提到的細節是 {待補}，沒有被補寫
