# L1-09 客訴／需求信處理建議

## 這張卡是什麼

| 欄位 | 內容 |
|---|---|
| 誰用 | 客服、業務、技服 |
| 什麼時候用 | 收到客訴或需求信 |
| 貼什麼進去 | 來信內容 |
| 產出 | 訴求拆解 + 建議處理步驟 + 回信草稿 |
| 要改的參數 | ①我方能承諾的範圍（一句話） |
| 可否排程 | 否 |
| 對客戶的好處 | 客戶的情緒跟真正的訴求被分開，回信不會越回越糟，也不會不小心承諾做不到的事 |

## 任務辨識

使用者出現下列意圖時啟用本技能：「客戶抱怨這個怎麼辦」「這封客訴幫我看」「他在氣什麼」

不屬於本技能的情況：一般往來信件的回覆草稿 —— 請改用對應的其他卡，不要勉強套用本卡格式。

## 提示詞本體（直接套用，{} 內為要改的參數）

```
以下是一封客戶來信。請幫我處理。

我方能承諾的範圍：{一句話，例：可換貨不可退款／可延期一週}

輸出：
【客戶真正要的】把情緒與訴求分開，訴求最多列 3 點
【建議處理步驟】依序 3～5 步，每步寫「誰做什麼」
【回信草稿】150 字內，先同理、再說明、最後給明確的下一步與時間點

規則：
- 不得承諾超出上述範圍的事
- 不確定的責任歸屬一律寫「我們會查證後回覆」，不要在信裡下判斷

---
（貼上來信）
```

## 全域規則（每次執行都適用）

- **不得寫入客戶名單、個資、報價金額、圖面與 BOM、內部代號**；使用者若貼入這類內容，
  在產出中以 {已遮蔽} 取代，並於結尾提醒一句。
- **產出一律視為草稿**，對外發送或正式使用前必須由人覆核。
- **找不到依據時明說「查無」**，不得自行推測填補。
- 全程繁體中文（台灣用語）。
- 本技能為唯讀輸出：不寫入任何檔案、不建立待辦、不變更平台紀錄。

## 5 分鐘檢核（交付現場用）

1. 用一封真的客訴跑（客戶名請先代稱）
2. 回信草稿沒有承諾超出授權範圍的事
3. 責任歸屬沒有在信裡被下定論
