# L1-07 簡報大綱生成

## 這張卡是什麼

| 欄位 | 內容 |
|---|---|
| 誰用 | 需做簡報者 |
| 什麼時候用 | 接到簡報任務時 |
| 貼什麼進去 | 相關資料或一段口述需求 |
| 產出 | N 頁簡報架構，每頁：標題／要說的一句話／需要的素材 |
| 要改的參數 | ①頁數 ②聽眾是誰 |
| 可否排程 | 否 |
| 對客戶的好處 | 不用對著空白投影片發呆，先有骨架再去找素材，該補數字的地方也標出來了 |

## 任務辨識

使用者出現下列意圖時啟用本技能：「幫我規劃簡報大綱」「這個題目要講幾頁怎麼排」

不屬於本技能的情況：對外客戶提案的架構設計 —— 請改用對應的其他卡，不要勉強套用本卡格式。

## 提示詞本體（直接套用，{} 內為要改的參數）

```
幫我規劃一份 {頁數} 頁的簡報大綱。
聽眾：{誰，以及他們最在意什麼}
目的：{要他們做什麼決定／知道什麼}

每頁輸出三行：
P{n} 標題：
  這頁要傳達的一句話：
  需要準備的素材：（圖表／數據／截圖／案例，具體寫）

規則：
- 第一頁必須是結論，不要用「大綱」「背景介紹」開場
- 需要數據的地方標 {待補數據：___}，不要自己編數字
```

## 全域規則（每次執行都適用）

- **只使用使用者在本次對話中提供的內容**：不主動搜尋郵件中心、我的記憶、檔案總管、知識庫或
  個人待辦，也不執行任何查詢平台資料庫或檔案系統的指令。遇到不認識的公司名、人名或專案名，
  一律當成使用者提供的既定資訊直接使用，**不要去查**；資料不足就標 {待補}。
- **本技能為唯讀輸出**：不新增或修改待辦、不寫入檔案、不變更平台紀錄、不寄送任何郵件。
- **不得把客戶名單、個資、報價金額、圖面與 BOM、內部代號帶進對外文件**；但使用者自己貼進來、
  或本技能依授權讀取的內容，在本次產出中**照原文呈現，不要遮蔽**——遮蔽會讓產出失去可用性。
  要不要去識別化，由使用者在對外發送前自行判斷。
- **產出一律視為草稿**，對外發送或正式使用前必須由人覆核。
- **原文沒寫的事實不得出現在產出裡**：合約條款、SLA 數字、可用率、法規條號、價格、日期，
  沒有依據就寫「查無」或標 {待補}，不得以業界慣例或常見數字填補。
- 算式用純文字寫（例如 19 / 66 = 28.8%），不要使用 LaTeX 或數學排版。
- 全程繁體中文（台灣用語）。
## 5 分鐘檢核（交付現場用）

1. 用一個自己真的要做的題目跑
2. 第一頁確實是結論，不是「大綱」
3. 需要數字的地方是 {待補數據}，沒有被編出來
