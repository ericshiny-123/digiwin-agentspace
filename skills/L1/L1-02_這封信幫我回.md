# L1-02 這封信幫我回（三種語氣）

## 這張卡是什麼

| 欄位 | 內容 |
|---|---|
| 誰用 | 全員 |
| 什麼時候用 | 收到需要回覆但懶得起頭的信 |
| 貼什麼進去 | 整封來信內容（含往來紀錄） |
| 產出 | 三個版本的回信草稿：正式／親切／簡短，各 150 字內 |
| 要改的參數 | ①我的立場（同意／婉拒／要更多資訊／爭取時間） |
| 可否排程 | 否 |
| 對客戶的好處 | 卡住不知道怎麼開頭的信，30 秒有三個版本可挑，改一改就寄得出去 |

## 任務辨識

使用者出現下列意圖時啟用本技能：「這封信幫我回」「幫我擬個回覆」「這樣回會不會太硬」

不屬於本技能的情況：整個收件匣的摘要、客訴或需求信的完整處理建議 —— 請改用對應的其他卡，不要勉強套用本卡格式。

## 提示詞本體（直接套用，{} 內為要改的參數）

```
以下是我收到的信。請幫我擬回覆草稿。

我的立場：{同意／婉拒／需要更多資訊／爭取時間，擇一}
我的身分：{職稱}

輸出三個版本，各不超過 150 字：
【A 正式】對外／對主管
【B 親切】平輩同事
【C 簡短】三句話以內

每個版本結尾附一行「這版適合用在：」說明。
規則：不要承諾信中沒有提到的事；金額、日期若原信沒寫就留 {待填}，不要自己編。

---
（貼上來信）
```

## 全域規則（每次執行都適用）

- **只使用使用者在本次對話中提供的內容**：不主動搜尋郵件中心、我的記憶、檔案總管、知識庫或
  個人待辦，也不執行任何查詢平台資料庫或檔案系統的指令。遇到不認識的公司名、人名或專案名，
  一律當成使用者提供的既定資訊直接使用，**不要去查**；資料不足就標 {待補}。
- **本技能為唯讀輸出**：不新增或修改待辦、不寫入檔案、不變更平台紀錄、不寄送任何郵件。
- **不得把客戶名單、個資、報價金額、圖面與 BOM、內部代號帶進對外文件**；但使用者自己貼進來、
  或本技能依授權讀取的內容，在本次產出中**照原文呈現，不要遮蔽**——遮蔽會讓產出失去可用性。
  要不要去識別化，由使用者在對外發送前自行判斷。
- **產出一律視為草稿**，對外發送或正式使用前必須由人覆核。
- **原文沒寫的事實不得出現在產出裡**：合約條款、SLA 數字、可用率、法規條號、價格、日期，
  沒有依據就寫「查無」或標 {待補}，不得以業界慣例或常見數字填補。
- 算式用純文字寫（例如 19 / 66 = 28.8%），不要使用 LaTeX 或數學排版。
- 全程繁體中文（台灣用語）。
## 5 分鐘檢核（交付現場用）

1. 貼一封自己真的收到的信，跑一次
2. 三個版本語氣真的不同，且都沒有承諾原信沒提到的事
3. 金額與日期若原信沒寫，確認有留 {待填} 而不是被編出來
