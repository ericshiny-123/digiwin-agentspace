# L1-13 訪談／面試逐字稿整理

## 這張卡是什麼

| 欄位 | 內容 |
|---|---|
| 誰用 | 人資、主管、業務 |
| 什麼時候用 | 面試或客戶訪談後 |
| 貼什麼進去 | 錄音或逐字稿 |
| 產出 | 重點摘要 + 依評分面向的原話引用 + 3 個待追問問題 |
| 要改的參數 | ①評分面向（3～5 個） |
| 可否排程 | 否 |
| 對客戶的好處 | 從憑印象評人變成憑原話評人，事後主管要看也有據可查 |

## 任務辨識

使用者出現下列意圖時啟用本技能：「面試整理一下」「這場訪談的重點」「依這幾個面向幫我看」

不屬於本技能的情況：一般會議的決議與待辦整理 —— 請改用對應的其他卡，不要勉強套用本卡格式。

## 提示詞本體（直接套用，{} 內為要改的參數）

```
以下是一場 {面試／客戶訪談} 的逐字稿。

評分面向：{面向1、面向2、面向3}

輸出：
【重點摘要】300 字內
【面向整理】每個面向：受訪者實際講過的原話（引用）｜我的觀察提示
【待追問】3 個這次沒問清楚的問題

規則：
- 「原話引用」必須是逐字稿裡真的出現的句子，不得改寫或綜合
- 不做人格評價、不做錄取建議，只整理事實

---
（貼上逐字稿）
```

## 全域規則（每次執行都適用）

- **只使用使用者在本次對話中提供的內容**：不主動搜尋郵件中心、我的記憶、檔案總管、知識庫或
  個人待辦，也不執行任何查詢平台資料庫或檔案系統的指令。遇到不認識的公司名、人名或專案名，
  一律當成使用者提供的既定資訊直接使用，**不要去查**；資料不足就標 {待補}。
- **本技能為唯讀輸出**：不新增或修改待辦、不寫入檔案、不變更平台紀錄、不寄送任何郵件。
- **不得把客戶名單、個資、報價金額、圖面與 BOM、內部代號帶進對外文件**；但使用者自己貼進來、
  或本技能依授權讀取的內容，在本次產出中**照原文呈現，不要遮蔽**——遮蔽會讓產出失去可用性。
  要不要去識別化，由使用者在對外發送前自行判斷。
- **產出一律視為草稿**，對外發送或正式使用前必須由人覆核。
- **原文沒寫的事實不得出現在產出裡**：合約條款、SLA 數字、可用率、法規條號、價格、日期，
  沒有依據就寫「查無」或標 {待補}，不得以業界慣例或常見數字填補。
- 算式用純文字寫（例如 19 / 66 = 28.8%），不要使用 LaTeX 或數學排版。
- 全程繁體中文（台灣用語）。
## 5 分鐘檢核（交付現場用）

1. 抽 2 句「原話引用」，回逐字稿找得到一模一樣的句子
2. 沒有出現人格評價或錄取建議
3. 待追問的問題確實是這次沒問到的
