# L2-SEC-04 每日資安情資摘要 【排程／每日】

## 這張卡是什麼

| 欄位 | 內容 |
|---|---|
| 誰用 | 資安人員 |
| 什麼時候用 | 每天自動跑（建議 09:00） |
| 貼什麼進去 | 無需貼——排程讀取已授權的情資來源；手動使用時可貼入情資清單 |
| 產出 | 只跟我們系統有關的情資摘要，寄到信箱 |
| 要改的參數 | ①我們在用的系統／廠牌清單 |
| 可否排程 | 是（每日）— 建議設為資安人員的每日排程 |
| 對客戶的好處 | 只看跟自己系統有關的，不用每天翻一堆用不到的資安新聞 |

> ⚠️ **建置前準備（務必先確認）**：本卡設計上假設平台能讀到「情資來源」，但截至 9 月測試
> 時確認過的工具只有 `user_files`／`knowledge`／`mail`／`task`，不含外部情資抓取（web 搜尋
> 或情資 API）。建置前請先比照 L1 卡的方式實際跑一次手動測試：
> ① 若平台有 web 搜尋或情資工具，直接排程即可；
> ② 若沒有，改成半自動版本：知識庫掛一份由資安人員每週手動更新的重點 CVE／廠牌公告清單，
>    本卡依這份知識庫（而非即時網路）產出每日摘要，並在交付現場讓客戶知道這是「定期更新」
>    而非「即時情資」。

## 任務辨識

使用者出現下列意圖時啟用本技能：「今天有什麼資安情資」「跟我們系統相關的漏洞」「每日威脅情資」「今天有沒有新的資安公告」

不屬於本技能的情況：客戶自己弱點掃描系統產出的報告（請改用 L2-SEC-01）。

## 提示詞本體（直接套用，{} 內為要改的參數）

```
每日整理資安情資，只保留跟我們相關的。

我們在用的系統與廠牌：{清單}

輸出（沒有相關項目就寫「今日無相關情資」，不要湊數）：
【與我們直接相關】情資標題｜影響的系統｜嚴重性｜建議動作
【值得知道】一行標題即可

規則：
- 來源不明確的情資不列入；不得誇大嚴重性
- 全文控制在 300 字內
- **讀取上限**：最多彙整 30 則情資來源；每則只看標題與摘要前 300 字，不得整篇複製原文

最後一步（必做，不可省略）：用郵件工具的 send 動作，把上面這份摘要寄到我自己的信箱，
主旨「每日資安情資摘要 {今天日期}」。寄出後在回覆最後一行寫「已寄出」或寄送失敗的原因。
產出只留在平台對話裡不算完成。
```

## 全域規則（每次執行都適用）

- **只讀取本卡明確授權的來源**（已授權的情資來源，以及使用者設定的系統廠牌清單）：
  不另外搜尋我的記憶、檔案總管或其他知識庫，也不執行任何查詢平台資料庫或檔案系統的指令。
  授權來源取不到資料時直接說「今日無相關情資」，**不要改用其他方式去找**。
- **只在交付產出時寫入**（把摘要寄到信箱）；**絕不修改、關閉或刪除任何既有的待辦、郵件或
  平台紀錄**。整理的結果只呈現在產出內容裡，不回頭改原始項目。
- **不得把客戶名單、個資、報價金額、圖面與 BOM、內部代號帶進對外文件**；但使用者自己貼進來、
  或本技能依授權讀取的內容，在本次產出中**照原文呈現，不要遮蔽**——遮蔽會讓產出失去可用性。
  要不要去識別化，由使用者在對外發送前自行判斷。
- **產出一律視為草稿**，對外發送或正式使用前必須由人覆核。
- **原文沒寫的事實不得出現在產出裡**：嚴重性評級、CVE 編號、影響範圍，沒有依據就不列入，
  不得以業界慣例或常見推測填補。
- 算式用純文字寫，不要使用 LaTeX 或數學排版。
- 全程繁體中文（台灣用語）。

## 排程設定注意

- 產出必須送到使用者原本就會看的地方（信箱），不可只留在平台內。
- 設定當下要當場算給客戶看每月預估點數，並教他怎麼關掉。
- 建置前請先確認上方「⚠️ 建置前準備」的情資來源問題，否則排程可能每天只輸出
  「今日無相關情資」而沒有實質內容，客戶會覺得這張卡沒有用。

## 5 分鐘檢核（交付現場用）

1. 手動觸發一次，確認收得到摘要，且不是每項都空白
2. 情資來源若用知識庫版本，確認知識庫更新日期有讓客戶知道
3. 字數在 300 字內，沒有整篇複製原始情資內文
