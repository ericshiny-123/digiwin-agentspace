# L2-SEC-05 設備告警日誌摘要

## 這張卡是什麼

| 欄位 | 內容 |
|---|---|
| 誰用 | IT 運維 |
| 什麼時候用 | 每日／每週檢視告警時 |
| 貼什麼進去 | 告警日誌（匯出的文字或 CSV） |
| 產出 | 告警分群＋需人工處理 Top 5＋次數異常提示 |
| 要改的參數 | ①要排除的已知雜訊類型清單 |
| 可否排程 | 可（每日）— 非必設，需客戶有自動匯出到平台可讀取位置才建議排程；否則維持手動貼入 |
| 對客戶的好處 | 知道哪些是雜訊、哪五件真的要人處理，不會被告警淹沒到乾脆全部不看 |

> ⚠️ **若要設為排程**：需確認平台能自動讀到當天匯出的告警日誌檔案（例如固定路徑的
> `user_files`）。沒有自動匯出機制就不要排程，改為人工每天貼入——一樣有效，只是不算
> 「不看會有損失」的用量引擎，離場門檻的「每日排程」建議優先用 L2-SEC-04。

## 任務辨識

使用者出現下列意圖時啟用本技能：「幫我整理這份告警日誌」「這些告警哪些要處理」「告警分群」「日誌太多看不完」

不屬於本技能的情況：已構成資安事件、需要判定法定通報時限（請改用 L2-SEC-03）。

## 提示詞本體（直接套用，{} 內為要改的參數）

```
以下是設備告警日誌。請整理。

已知可忽略的雜訊：{類型清單}

輸出：
【告警分群】類型｜次數｜首次與最近發生時間
【需人工處理 Top 5】告警內容｜為什麼需要人處理｜建議先做什麼
【次數異常】跟平常比明顯變多的類型（沒有基線資料就寫「無基線可比」）

規則：
- 次數一律實際計數，不得估算
- **讀取上限**：單次最多處理 2,000 行日誌；超過只處理最新 2,000 行，結尾註明「另有 N 行未處理」

（若本次為排程自動執行）最後一步（必做，不可省略）：用郵件工具的 send 動作，把上面這份摘要
寄到我自己的信箱，主旨「設備告警日誌摘要 {今天日期}」。寄出後在回覆最後一行寫「已寄出」或
寄送失敗的原因。手動對話模式下不需要寄信，直接在對話中呈現即可。
```

## 全域規則（每次執行都適用）

- **只讀取本卡明確授權的來源**（使用者貼入的告警日誌，或排程讀取的已授權日誌檔案）：
  不另外搜尋我的記憶、檔案總管或知識庫，也不執行任何查詢平台資料庫或檔案系統的指令。
  授權來源取不到資料時直接說「查無」，**不要改用其他方式去找**。
- **只在排程自動執行時才寫入**（把摘要寄到信箱）；**絕不修改、關閉或刪除任何既有的待辦、
  郵件或平台紀錄**。手動對話模式下不寫入任何平台紀錄。
- **不得把客戶名單、個資、報價金額、圖面與 BOM、內部代號帶進對外文件**；但使用者自己貼進來、
  或本技能依授權讀取的內容，在本次產出中**照原文呈現，不要遮蔽**——遮蔽會讓產出失去可用性。
  要不要去識別化，由使用者在對外發送前自行判斷。
- **產出一律視為草稿**，對外發送或正式使用前必須由人覆核。
- **原文沒寫的事實不得出現在產出裡**：告警嚴重性、次數、異常判斷，沒有依據就寫「無基線可比」，
  不得以業界慣例或常見推測填補。
- 算式用純文字寫（例如 19 / 66 = 28.8%），不要使用 LaTeX 或數學排版。
- 全程繁體中文（台灣用語）。

## 排程設定注意

- 僅在客戶有自動匯出日誌到平台可讀取位置時才建議排程；否則維持手動貼入。
- 若設為排程，產出必須送到信箱，不可只留在平台內；設定當下算給客戶看每月預估點數。

## 5 分鐘檢核（交付現場用）

1. 貼入一份測試日誌，確認分群次數與原始筆數吻合
2. Top 5 的「為什麼需要人處理」不是空話，是具體理由
3. 超過 2,000 行的日誌，確認有註明「另有 N 行未處理」
