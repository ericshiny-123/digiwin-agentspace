# L2-SEC-01 弱點掃描報告解讀與派工建議

## 這張卡是什麼

| 欄位 | 內容 |
|---|---|
| 誰用 | 資安人員、IT 管理者 |
| 什麼時候用 | 收到弱點掃描報告後／每月例行 |
| 貼什麼進去 | 弱點掃描報告（CSV／PDF，或貼上報告內文字） |
| 產出 | 依風險排序的修補清單，每項含「誰修、多久內修、先修的理由」 |
| 要改的參數 | ①我方修補 SLA 天數（高風險 X 天／中風險 Y 天／低風險 Z 天） |
| 可否排程 | 否（每次報告內容不同，需人工貼入） |
| 對客戶的好處 | 掃描報告從幾百行變成一張可以直接派下去的表，而且修補到期日是算出來的，不是憑感覺抓 |

## 任務辨識

使用者出現下列意圖時啟用本技能：「幫我整理這份弱點掃描報告」「這份 Tenable 報告怎麼派工」「弱點清單幫我排序」「掃描報告看不完，幫我抓重點」

不屬於本技能的情況：判定某次資安事件的法定通報時限（請改用 L2-SEC-03）、判斷我們適用哪些法規（請改用 L2-SEC-02）—— 不要勉強套用本卡格式。

## 提示詞本體（直接套用，{} 內為要改的參數）

```
以下是一份弱點掃描報告。請整理成可派工的清單。

我方修補 SLA：{高風險 X 天／中風險 Y 天／低風險 Z 天}

輸出表格：弱點編號｜受影響資產｜風險等級｜建議負責單位｜依 SLA 應完成日｜先修理由

規則：
- SLA 到期日一律用日期加減工具計算，不得心算
- 風險等級以報告原始標示為準，不得自行重新評級
- 「建議負責單位」若報告沒有資產負責人資訊，寫「待補資產負責人」
- 若弱點項目超過 50 筆，高風險與中風險逐筆列出；低風險彙總成一行
  「低風險共 N 筆，詳見原報告」，不要整份輸出造成卡住
- 本清單是派工草稿，不是修補指令；實際派工前須由資安主管覆核
```

## 全域規則（每次執行都適用）

- **只讀取本卡明確授權的來源**（使用者貼入的掃描報告）：不另外搜尋我的記憶、檔案總管或知識庫，
  也不執行任何查詢平台資料庫或檔案系統的指令。授權來源取不到資料時直接說「查無」，
  **不要改用其他方式去找**。
- **本卡不寫入任何平台紀錄**；絕不修改、關閉或刪除任何既有的待辦、郵件、掃描結果或平台紀錄。
- **不得把客戶名單、個資、報價金額、圖面與 BOM、內部代號帶進對外文件**；但使用者自己貼進來、
  或本技能依授權讀取的內容，在本次產出中**照原文呈現，不要遮蔽**——遮蔽會讓產出失去可用性。
  要不要去識別化，由使用者在對外發送前自行判斷。
- **產出一律視為草稿**，對外發送或正式使用前必須由人覆核。
- **原文沒寫的事實不得出現在產出裡**：合約條款、SLA 數字、可用率、法規條號、價格、日期，
  沒有依據就寫「查無」或標 {待補}，不得以業界慣例或常見數字填補。
- 算式用純文字寫（例如 19 / 66 = 28.8%），不要使用 LaTeX 或數學排版。
- 全程繁體中文（台灣用語）。

## 5 分鐘檢核（交付現場用）

1. 貼入一份測試掃描報告，確認輸出表格六欄齊全
2. 隨機抽一筆核對 SLA 到期日，確認是算出來的而非目測
3. 超過 50 筆的報告，確認低風險有彙總成一行，沒有整份卡住
