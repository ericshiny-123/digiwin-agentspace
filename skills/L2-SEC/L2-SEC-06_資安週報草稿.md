# L2-SEC-06 資安週報草稿 【排程／每週】

## 這張卡是什麼

| 欄位 | 內容 |
|---|---|
| 誰用 | 資安主管 |
| 什麼時候用 | 每週五下午自動跑（建議 16:00） |
| 貼什麼進去 | 無需貼——排程讀取本週事件紀錄與個人待辦 |
| 產出 | 週報草稿：本週事件／重點案件／風險提醒／下週重點 |
| 要改的參數 | ①要呈報給誰 |
| 可否排程 | 是（每週）— 建議必設 |
| 對客戶的好處 | 主管要的週報從半小時變五分鐘，而且數字是從紀錄算出來的，被追問也答得出來 |

## 任務辨識

使用者出現下列意圖時啟用本技能：「幫我生資安週報」「這週資安事件整理」「資安週報草稿」

不屬於本技能的情況：全員通用的工作週報（請改用 L1-06，不要勉強套用本卡格式）。

## 提示詞本體（直接套用，{} 內為要改的參數）

```
產出本週資安週報草稿，呈報對象：{對象}。

讀取本週的事件紀錄與個人待辦，輸出四區：
【本週事件】件數｜已結案｜處理中
【重點案件】最多 3 件，各 3 行
【風險提醒】依實際紀錄推導，沒有就寫「本週無新增風險」
【下週重點】

規則：
- 不得寫入系統中沒有紀錄的事件；數字一律實際計算
- 全文控制在 500 字內
- **讀取上限**：最多彙整本週 30 筆事件與待辦紀錄，每筆只看前 300 字

最後一步（必做，不可省略）：用郵件工具的 send 動作，把這份週報草稿寄到我自己的信箱，
主旨「資安週報草稿 {本週起訖日}」。寄出後在回覆最後一行寫「已寄出」或寄送失敗的原因。
產出只留在平台對話裡不算完成。
```

## 全域規則（每次執行都適用）

- **只讀取本卡明確授權的來源**（平台事件紀錄、個人待辦）：不另外搜尋我的記憶、檔案總管或
  知識庫，也不執行任何查詢平台資料庫或檔案系統的指令。授權來源取不到資料時直接說「查無」，
  **不要改用其他方式去找**。
- **只在交付產出時寫入**（把週報寄到信箱）；**絕不修改、關閉或刪除任何既有的待辦、事件紀錄
  或平台紀錄**。整理的結果只呈現在產出內容裡，不回頭改原始項目。
- **不得把客戶名單、個資、報價金額、圖面與 BOM、內部代號帶進對外文件**；但使用者自己貼進來、
  或本技能依授權讀取的內容，在本次產出中**照原文呈現，不要遮蔽**——遮蔽會讓產出失去可用性。
  要不要去識別化，由使用者在對外發送前自行判斷。
- **產出一律視為草稿**，對外發送或正式使用前必須由人覆核。
- **原文沒寫的事實不得出現在產出裡**：事件件數、處理狀態、風險項目，沒有依據就寫「查無」，
  不得以業界慣例或常見推測填補。
- 算式用純文字寫（例如 19 / 66 = 28.8%），不要使用 LaTeX 或數學排版。
- 全程繁體中文（台灣用語）。

## 排程設定注意

- 產出必須寄到使用者信箱或個人待辦。
- 設定當下要揭露每月預估點數並教客戶怎麼關。
- **平台已知限制**：每週 cron 的下次執行時間計算有缺陷（只有「今天」與「明天」算得對，
  更遠的星期會落在不可預期的未來日期，詳見 OPS-01／部署紀錄 v3 第六節）。設定時改用
  「每日觸發＋提示詞最前面加星期守門」：在 **cron 的 prompt 欄位**最前面加一句「先確認
  今天星期幾，如果不是星期五，直接回覆『非週五，略過』並立即結束，不要啟用任何技能、
  不要呼叫任何工具」——這段守門文字只加在 cron 設定裡，不是 SKILL.md 本體。

## 5 分鐘檢核（交付現場用）

1. 手動觸發一次，確認四區都有內容或誠實寫「本週無新增風險」
2. 沒有出現系統裡查不到的事件
3. 確認 cron 設定是「每日＋星期守門」而不是直接選每週五（平台缺陷未修復前）
