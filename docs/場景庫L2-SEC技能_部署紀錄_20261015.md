## 二、Feng 人格掛載（02、03）

L2-SEC-02、L2-SEC-03 是合規判斷型卡片，不開放 Main Agent 直接叫用，改掛到「法規遵循專家」
（id `e91364b9-ce32-4be3-9208-a9d61f2809d7`）底下，`skillIds` 由 11 個增為 13 個。

⚠️ **新 API 發現，`agentspace-edge-ops` 技能手冊沒記載**：`/api/fengs/{id}` **不支援 PATCH**
（回 404 `Cannot PATCH`）。正確做法是整包 `PUT`：先 `GET /api/fengs` 拿到該人格的完整物件，
原封不動 spread，只改 `skillIds` 陣列，再整包 PUT 回去。

## 四、平台行為筆記／新發現

| # | 發現 | 影響與做法 |
|---|---|---|
| 1 | 手動把長 base64 字串原樣打進 JS 參數，**內容會在轉錄階段悄悄損壞**——位元組／字元數不變、SHA-256 卻對不上，用傳統「送出內容 vs. 重新讀回」比對會誤判成功 | 改用「本機先切 800 字 chunk，每個 chunk 附 16 碼雜湊、瀏覽器端逐塊校驗再串接、串完再比對本機原檔整檔 SHA-256」的流程，6 張全數驗證一致 |
| 2 | `/api/fengs/{id}` 不支援 PATCH | 見上方「二」，改用整包 PUT |
| 3 | 寄信核准卡 **5 分鐘沒人處理會自動過期**，不寄出 | 排程卡（04、06）的信件動作在交付現場要提醒客戶：排程真的跑了但沒人在 5 分鐘內看對話，週報／情資摘要就不會真的寄到信箱，只留在對話紀錄裡 |
| 4 | L2-SEC-03：事件紀錄顯示「注入技能 L2-SEC-03」，但模型回覆最後一行說「技能目前不在技能庫，沒走標準判定流程」，不過實際回答品質沒受影響（沒有給未確認期限、算式與引註都對） | **開放問題，待產品端查**，懷疑與已知的「執行沙箱有時掛不到技能自己的 SKILL.md／references／scripts」限制同一根因，但沒有確鑿證據 |
| 5 | L2-SEC-04 卡片原本寫的 ⚠️「情資來源工具待平台實測確認（沙箱可能沒有對外連網能力）」**是多慮了**——實測證實沙箱確實連得到 CISA KEV、MSRC、Fortinet PSIRT 並抓回即時資料 | 卡片內的 ⚠️ 註記可以拿掉；原本設計的「半自動／只用知識庫」退路可能根本不需要 |
