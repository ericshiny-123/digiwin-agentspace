# AgentSpace / Edge 場景庫 v1.4

> 用途：交付現場給客戶選的「結構化菜單」。取代空白對話框。
> 設計比例：**L1 全員通用 OA 為主（撐日活躍與用量）、L2 職能包為輔（撐深度與續約論述）**。
> 每張卡的驗收門檻：**客戶第一次操作可在 5 分鐘內完成**（含貼資料、改參數、看結果）。
>
> **v1.1 更新**（依 [[AgentSpace交付方案_製造業IT視角評估_20260908]]）：
> ①新增 **L2-MIS 製造業 IT／MIS 包 6 張**，核心為 ERP 操作問答 —— v1.0 的 21 張卡對製造業 IT
> 只有約 3 張有用，因為原「資安／IT 運維包」是寫給有資安專責人員的公司用的，
> 而台灣中型製造業只有什麼都管的 MIS，**這兩種不是同一種人**；
> ②全庫通則改為**技術管制＋使用守則兩層**（原版只有使用守則，IT 不會接受、稽核也過不了）；
> ③所有排程卡新增**每月預估點數**欄位（避免客戶第四週發現「被偷燒點數」而一次全關）。
>
> **v1.2 更新**：全庫 41 張卡、場景精靈與推薦組合，**每一項都補上「💡 對客戶的好處」一行**。
> 交付現場介紹任何一張卡時，先講這一行，再講怎麼操作 —— 客戶要的是「這能幫我省掉什麼麻煩」，
> 不是「這張卡有哪些功能」。這一行也是顧問的話術底稿，可直接照唸。
>
> **v1.3 更新**：新增「場景庫整體規劃總表」—— 41 張卡一覽，含**每張卡的輸入資料（執行時要拿什麼）**
> 與對應的交付段落，並整理出「需要客戶先給文件的 7 張卡」與各自的替代做法。
> 這張總表是交付顧問行前組菜單與現場走查的單一索引。
>
> **v1.4 更新**：依 [[AgentSpace交付方案_交付團隊可行性驗證_20260908]]，
> ERP 客製說明改為**向內部 ERP 顧問取得**，不向客戶索取 —— 客製是我們做的，
> 說明在我方導入文件裡，客戶自己通常沒寫下來。這比向客戶要快得多，也是我方獨有優勢。

## 選卡與排序的原則：先好玩，才好用，才會每天用

| 階段 | 交付段落 | 挑哪種卡 |
|---|---|---|
| **① 先好玩** | B 段 | 挑**三十秒就有結果、而且用他自己的東西**的卡（L1-04 長文件摘要、L2-MIS-03 log 找異常、L2-MIS-04 原廠文件）。<br>IT／MIS 用顧問預先備妥的安全素材，不要逼他當場拿敏感檔冒險 |
| **② 才好用** | C／D／F 段 | 挑**跟他本職工作最貼**的卡（附錄 B 推薦組合），並讓他自建一張 |
| **③ 才會每天用** | E 段 | 只挑**不看會有損失**的卡設排程（總表讀法②的 8 張），產出送信箱或待辦 |

> **好玩不等於娛樂**：是三十秒內用他自己的東西產出一次結果的驚喜。
> 用假資料表演出來的驚喜，客戶回座位面對自己的資料就消失了。
> 但**好玩撐不過兩週**——B 段之後必須立刻接 C／D／F 把它變成工具。

## 場景卡格式（7 欄，比照 JD 7 欄格式精神）

| 欄位 | 說明 |
|---|---|
| 卡號／名稱 | L1-xx / L2-<職能>-xx |
| 誰用 | 職務角色 |
| 什麼時候用 | 觸發時機與頻率（每日／每週／不定期） |
| 貼什麼進去 | 輸入物 |
| 產出 | 明確的輸出形式與長度 |
| 要改的參數 | **限 1～2 個**，超過 2 個代表這張卡設計失敗 |
| 可否排程 | 是／否；「是」者為用量引擎，交付時優先推。**排程卡必須同時標示每月預估點數** |

## 全庫通則（兩層，寫在菜單手冊第一、二頁）

> v1.0 只有「使用守則」一層 —— 那是要求使用者自律。製造業 IT 的原話是：
> 「使用者一定會貼，因為方便。我要的是技術管制。」而客戶稽核（日系／歐系車廠）也只認技術管制。

### 第一層：技術管制（由我方在交付前完成設定，並在段 0 出示證據）

| 項目 | 交付時必須給出的答案 |
|---|---|
| 資料落地 | Edge 為地端主機，資料不出廠的具體邊界；哪些情況會有外部連線 |
| 上傳阻擋 | 是否可禁止特定副檔名（.dwg／.step／.pdf 圖面等）或含特定關鍵字的內容上傳 |
| 稽核 log | 誰在什麼時候貼了什麼是否可查；**保留期限多久**；客戶稽核時能否自行調閱 |
| 權限範圍 | 誰看得到誰的對話；管理者看得到什麼 |
| 信箱存取 | 排程讀信用什麼帳號連、憑證存在哪、主機失竊的影響範圍 |

> ⚠️ 上述能力目前**尚未逐項向產品端確認**（見交付方法論待確認 #9、#11）。
> 若某一項做不到，段 0 必須誠實告知客戶做不到並說明替代管制，**不得含糊帶過**。

### 第二層：使用守則（寫給使用者）

1. 不得貼入：客戶名單、個資、報價金額、圖面與 BOM、內部代號（分身／BQ 代號等）、`98_機密` 等級資料
2. 產出一律視為**草稿**，對外發送前必須人工覆核
3. 找不到依據時要求 AI 明說「查無」，不得自行推測填補

### 排程卡的點數揭露規則（v1.1 新增）

每一張可排程的卡，交付現場必須當場做三件事，否則不算完成設定：

1. **算給客戶看**：這個排程每月大約消耗多少點數（依客戶實際資料量估）
2. **教客戶怎麼關**：教客戶怎麼關，客戶才敢開
3. **約定 D+7 回饋**：第 7 天我方主動寄「這個排程本週花了 X 點、你開啟了 Y 次」

連續 2 週開啟率低於 50% 者，主動建議改成每週或關閉 —— **不要放著讓客戶自己在第四週發現**。

> 各卡標示的「每月預估點數」為**尚未實測的推估區間**，須在首次試跑後以實際數據校正。

## 總表的三個讀法

**① 依「層級」看比例**

| 層級 | 張數 | 撐什麼 | 交付時的角色 |
|---|---|---|---|
| L1 全員通用 OA | 15 | 日活躍與用量 | 每個人都要選，是用量主體 |
| L2-MIS 製造業 IT／MIS | 6 | **窗口本人的動機** | 製造業客戶的預設職能包，第一張就講 |
| L2-SEC 資安專責 | 6 | 續約論述 | **只在客戶有資安專責人員時才排** |
| L2-HR／SAL／FIN／MFG | 14 | 部門深度 | 依客戶到場部門選 1～2 包 |
| **合計** | **41** | | |

**② 依「排程」看用量引擎**（可排程卡共 8 張，是離場後唯一會持續消耗算力的機制）

| 卡號 | 建議時間 | 給誰 | 為什麼是「不看會有損失」 |
|---|---|---|---|
| L1-01 晨間信件摘要 | 每日 08:30 | 主管、業務、行政、財會 | 今天要回哪三封信 |
| L1-12 今日待辦排序 | 每日 09:00 | 全員 | 今天有什麼逾期了 |
| **L2-MIS-06 系統健檢** | **每日 08:00** | **IT／MIS** | **昨晚備份到底有沒有成功** |
| L2-SEC-04 資安情資 | 每日 09:00 | 資安專責 | 跟我們系統有關的漏洞 |
| L2-SEC-05 告警日誌 | 每日 | IT 運維 | 今天哪五件要人處理 |
| L1-06 週報草稿 | 每週五 16:00 | 全員 | 週報要交了 |
| L2-SEC-06 資安週報 | 每週五 16:00 | 資安主管 | 週報要交了 |
| L1-15 知識沉澱 Wiki | 每週五 17:00 | 全員 | 這週的做法別忘了 |

> **交付規則**：每人 ≥2 個排程、其中 ≥1 個每日。**MIS 的每日排程用 L2-MIS-06，不要用 L1-01**
> —— IT 信不多，重要的事同事會直接打電話。

**③ 依「輸入資料」看行前準備**

| 需要客戶先給的文件 | 對應卡 | 沒拿到的後果 | 替代做法 |
|---|---|---|---|
| **鼎新 ERP 操作手冊＋客戶客製說明** | L2-MIS-01 | **全庫最高價值的卡建不起來**，製造業窗口失去動機 | **客製說明改向內部 ERP 顧問取得**（客製是我們做的，說明在導入文件與客製規格書裡，客戶自己通常沒寫下來）；仍拿不到才只掛原廠手冊 |
| 客戶公司規章 | L2-HR-03 | 人資包少一張 | 改跑 L2-HR-01／02 |
| 客戶費用報銷規定 | L2-FIN-01 | 財會包少一張 | 改跑 L2-FIN-02 |
| 客戶月結流程說明 | L2-FIN-03 | 財會包少一張 | 同上 |
| 監看主機與路徑清單 | L2-MIS-06 | **IT 的每日排程設不起來** | 現場請 IT 當場列（約 10 分鐘，需算進 E 段） |
| 客戶系統與廠牌清單 | L2-SEC-04 | 情資摘要會列一堆不相關的 | 現場問 IT 口述即可 |
| 修補 SLA 天數 | L2-SEC-01 | 到期日算不出來 | 現場問；沒有政策就先用客戶口頭值並標「暫定」 |

### ⭐⭐ L2-MIS-01 ERP 操作問答 【每日／全場最高價值】

> 💡 **對客戶的好處**：同事自己查得到怎麼開單，資訊課一天少接十通電話；新人不用一直問人也能上手。這是全庫對交付窗口本人最有感的一張。

| | |
|---|---|
| 誰用 | 全公司（由 IT／MIS 建置，同事自助使用） |
| 什麼時候用 | 任何人不知道「這張單怎麼開」「為什麼過不了」「這個欄位是什麼意思」的時候 |
| 貼什麼進去 | 問題描述，或錯誤訊息截圖／文字 |

**為什麼這張卡值得整個包**：IT／MIS 每天接 15～25 通電話，其中最大宗就是 ERP 操作問題。
這張卡讓同事自助解決，**窗口一天可以少接十通電話**。
而且這是鼎新獨有、別家 AI 做不到的能力（吃自家 ERP 手冊）。

**預鑄提示詞**
```
你是我們公司的 ERP 操作助手。依據知識庫中的 ERP 操作手冊與本公司客製說明回答問題。

回答格式：
【操作步驟】逐步條列，寫清楚在哪個模組、哪個作業代號、按哪個按鈕
【出處】手冊章節或本公司客製說明的檔名與段落
【如果還是不行】列出 2～3 個常見原因（權限不足／單據狀態／前置單未完成等）
【要找誰】超出操作範圍需要 IT 或顧問處理的，直接說要找誰

規則（重要）：
- 只能依據知識庫內容回答。知識庫查不到就直接寫「手冊與客製說明中查無此項，請洽資訊課」，
  不得用一般 ERP 常識或其他版本的做法代答
- 本公司客製規則與原廠手冊衝突時，以本公司客製說明為準，並註明兩者不同
- 不得指導任何涉及資料庫直接修改、後台改單、繞過簽核的做法
- 涉及金額、成本、售價的欄位說明只解釋欄位意義，不解讀數字
```

**建置前置條件**：需掛載 ERP 操作手冊＋客戶客製說明文件。
**授權與內容範圍須先由產品／ERP 事業確認**（見交付方法論待確認 #7）。
**5 分鐘檢核**：拿現場同事最近問過的三個問題實測，至少 2 個答得出來且出處正確。

| 要改的參數 | ①要監看的主機與路徑清單 ②時間（08:00） |

輸出（一切正常就寫「今日無異常」，不要湊字數）：
【昨晚備份】成功／失敗／未執行，附時間與檔案大小
【磁碟空間】低於 {門檻}% 的才列
【異常登入】非上班時段或連續失敗的登入紀錄
【今天要處理的】最多 3 項，依急迫性排序

規則：

# 附錄 A：場景精靈（D 段用）

> 這是交付現場讓客戶「自建一張卡」的引導提示詞。

```
你是場景設計精靈。你的任務是問我五個問題，然後幫我生成一張可以重複使用的場景卡。

規則：
- 一次只問一個問題，等我回答完再問下一個
- 我的回答如果太模糊，追問一次，但不要超過一次
- 五題問完後才輸出，中途不要先給我半成品

五個問題：
1. 你每週會重複做超過兩次的事情是什麼？（越具體越好）
2. 做這件事的時候，你手上會有什麼東西？（信／文件／錄音／表格／什麼都沒有）
3. 做完之後成果要給誰？他拿到之後要做什麼？
4. 成果大概要多長？有沒有固定格式？
5. 有什麼是絕對不能出現在成果裡的？（客戶名、金額、個資、內部代號）

最後輸出一張場景卡，格式如下：
──────────
【卡名】（10 字內）
【誰用】
【什麼時候用】
【貼什麼進去】
【產出】
【要改的參數】（最多兩個，用 {} 標示）
【可否排程】是／否，若是，建議時間
【提示詞】完整可直接複製使用，含第 5 題的禁止事項
──────────

輸出後問我一句：「要不要現在用你手上真的資料跑一次？」
```

**D 段的驗收**：每人產出 1 張卡，且**當場用真實資料跑通一次**。
只生成沒跑通的不算完成——沒跑過的卡，客戶不會再打開第二次。
